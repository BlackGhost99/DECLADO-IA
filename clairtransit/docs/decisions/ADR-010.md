# ADR-010 : Contrôle d'un code présent et décision attribuée, invalidés par empreinte

Statut : Accepté (lot 2).

## Décision

- Le code lu reste une `CodeObservation` immuable (valeur brute, intitulé du champ, code normalisé, nature douanier / fournisseur / incertaine). Le changer crée une nouvelle observation et garde l'ancienne.
- Le contrôle (`CodeCheck`) suit l'algorithme du §8 de la conception, sans IA, et enregistre ses constats. Les états sont : `missing`, `ambiguous`, `incomplete`, `not_found`, `edition_mismatch` et `recognized`. `inconsistent` existe dans le modèle, mais aucune règle de cohérence marchandise/code n'est encore encodée : un constat le dit explicitement.
- `recognized` signifie seulement « retrouvé dans l'édition cible ». Seule une `ClassificationDecision` humaine, motivée et attribuée (confirmer, compléter, remplacer avec source), retient un code. Elle est en ajout seul.
- Le contrôle et la décision portent l'empreinte des données dont ils dépendent : observations actives, désignation, attributs, origine, édition. Si l'une change, ils deviennent périmés (« à revoir »), sans être effacés. Une décision exige le contrôle le plus récent, non périmé, et la version courante de la marchandise (sinon 409).
- Une édition de consultation historique ajoute toujours un constat `HISTORICAL_REFERENCE` bloquant pour un calcul opérationnel.

Référence : `docs/specifications/02-conception-technique.md` §4 (Contrôle des codes), §8, §10.
