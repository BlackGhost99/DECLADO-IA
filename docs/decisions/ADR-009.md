# ADR-009 : Pièces dans un stockage privé, accès par lien temporaire

Statut : Accepté (lot 2).

## Décision

- Les originaux sont écrits derrière l'interface `apps.documents.storage.PrivateStorage`. L'implémentation livrée, `LocalPrivateStorage`, écrit sous `PRIVATE_STORAGE_ROOT/documents/<société>/<clé aléatoire>` (fichiers 0600, aucun nom d'origine dans le chemin, hors de toute racine servie).
- Un adaptateur compatible S3 se branchera derrière la même interface quand l'hébergement sera choisi (question ouverte). Il n'est pas simulé.
- Le type est déterminé par le contenu (signature, structure), jamais par l'extension ou l'en-tête du navigateur : ceux-ci doivent seulement être cohérents. Un fichier refusé n'est pas conservé ; un fichier protégé ou endommagé est conservé et signalé, sans aperçu.
- Les octets ne sont servis que par `GET /api/v1/files/<jeton>/<nom>` : jeton signé de courte durée (`DOCUMENT_LINK_TTL_SECONDS`, 300 s par défaut), lié à l'utilisateur et à la société, émis après contrôle d'accès. L'affiliation est revérifiée à chaque lecture.
- Réponses : `X-Content-Type-Options: nosniff`, `Cache-Control: private, no-store`, `X-Frame-Options: SAMEORIGIN` (aperçu intégré) et une politique CSP stricte pour les images. Le PDF n'a pas de CSP stricte car le lecteur intégré du navigateur ne s'afficherait pas.
- L'aperçu .xlsx renvoie des cellules en texte : valeurs en cache et formules affichées, jamais recalculées ; liaisons externes jamais suivies ; taille décompressée bornée.

## Conséquences

La sauvegarde doit couvrir ensemble la base et `PRIVATE_STORAGE_ROOT` (volume `private` sous Docker). Une pièce liée à un dossier n'est jamais supprimée par le parcours courant ; le remplacement crée une nouvelle version.
